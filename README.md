# 교실온 — 교실 환경 분석 웹 앱

## 2026-09-30 추가 기능

- **기록 수정·삭제**: 환경 기록의 수정/삭제 버튼 또는 분석 결과 하단 기록 관리에서 사용합니다. 수정은 입력 화면에 기존 값을 채우고 같은 기록을 갱신합니다. 취소 시 변경되지 않으며 삭제는 확인 창을 거칩니다.
- **개선 전후 비교**: 환경 기록 하단에서 같은 교실의 두 시점을 선택합니다. 후 시점은 전 시점보다 늦어야 하며 실제·예시 기록 간 비교는 막습니다. 점수와 5개 항목의 실제 변화량 및 상태 변화를 표시합니다.
- **시간대별 평균 분석**: 조회한 기간 내 기록을 현지 시간 기준 1시간 단위로 묶습니다. 교실과 예시 여부별로 분리하여 평균과 측정 건수를 보여주며, 위 항목 선택에서 CO₂·온도 등으로 전환합니다. 1회 측정은 단일 측정으로 표시합니다.
- **항목별 판정 이유**: 적정 범위 및 상한/하한과의 차이, 주의 범위 해당 여부와 항목 점수·계산식을 표시합니다.
- **개선 우선순위**: 개선 필요 → 주의 순서, 같은 단계에서는 관련 체감 불편을 우선합니다. 나머지 동순위는 기존 항목 순서입니다. 권장 행동도 동일한 순서로 정렬합니다.

기존 로컬 기록은 그대로 사용합니다. **Supabase 연결 시 수정·삭제는 브라우저에만 반영하며 공유 원본을 바꾸지 않습니다.** 원본이 다시 조회되어도 이 브라우저의 수정/삭제 상태를 우선합니다. 공유 원본의 수정·삭제는 사용자 인증과 소유자별 권한을 추가한 뒤 확장해야 합니다. 로컬 저장소를 지우면 이 변경 상태도 사라집니다. 삭제 기록은 재등장을 방지하기 위해 로컬에 삭제 표시로 보관합니다.

프로젝트명: **교실 환경 데이터 분석을 통한 맞춤형 학습환경 개선**

별도 패키지 설치 없이 실행하는 HTML/CSS/JavaScript 앱입니다. 외부 폰트·CDN·API 키가 없어도 동작합니다. Node.js 20 이상과 최신 Chrome/Edge를 사용하세요.

## 실행

Windows에서는 `start-app.cmd`를 더블클릭하면 서버를 백그라운드에서 실행하고 브라우저를 엽니다. 이미 실행 중이면 기존 서버를 사용합니다. 컴퓨터를 다시 켠 뒤에는 이 파일을 다시 실행하세요. 앱은 온라인에 배포된 것이 아니라 이 컴퓨터의 서버로 실행됩니다.

이 폴더에서 터미널을 열고 실행합니다.

```sh
node server.mjs
```

브라우저에서 http://localhost:4173 을 엽니다. 종료는 터미널에서 Ctrl+C입니다. HTML 파일을 직접 더블클릭하지 말고 서버로 실행하세요(ES 모듈 사용). 포트 변경은 환경 변수 `PORT`로 가능합니다. 로컬 서버는 127.0.0.1에만 바인딩됩니다.

```sh
node --test tests/*.test.mjs
```

## 발표 순서 (3~5분)

1. **환경 측정**에서 기본 정보·5개 환경값·체감 불편을 설명합니다. `예시 값 채우기` 후 분석합니다.
2. **분석 결과**의 68점과 항목별 상태를 설명합니다. 측정값이 주의이면 환기·조명·냉난방 등의 제안이 나옵니다.
3. **환경 기록**에서 `발표용 예시 기록 추가`를 누릅니다. 어제 9~16시의 기록 8개가 별도 `예시 교실`로 추가됩니다. 그래프 항목을 CO₂로 변경해 비교합니다. 예시 추가는 중복 방지하며 클라우드로 전송하지 않습니다.
4. **분석 기준**에서 IPO 흐름과 점수 계산식을 설명합니다. 예시 값으로 직접 분석·저장한 기록은 일반 기록으로 저장됩니다.

## 계산 기준 v1.0

이 범위는 **학습용 자체 예시 기준**이며 법적 기준이나 공인 쾌적도 지수가 아닙니다. 계절·수업 상황별 기준 검토는 후속 연구 과제입니다.

|항목|적정 (100점)|주의 (60점, 적정 범위 제외)|개선 필요 (20점)|
|---|---|---|---|
|온도|20~26℃|16~30℃|주의 범위 밖|
|습도|40~60%|30~70%|주의 범위 밖|
|CO₂|250~1000ppm|250~1500ppm|1500 초과|
|조도|300~750lx|150~1000lx|주의 범위 밖|
|소음|0~50dB|0~65dB|65 초과|

모든 경곗값 포함. 종합 점수는 5항목의 단순 평균을 반올림하며, 80 이상 쾌적 / 60 이상 주의 / 60 미만 개선 필요입니다. 최저 점수는 20점입니다. 입력 가능한 전체 범위는 `analysis.js`의 `min/max`에서 확인합니다. 센서값의 정확성을 보증하거나 건강·학업 성과를 예측하지 않습니다.

체감 불편은 별도 확인 제안으로 반영하며 점수에는 영향을 주지 않습니다. 30명 이상은 환기 점검 안내를 추가하며, 오후 4시 이후 조도가 낮으면 늦은 시간 조명 안내를 추가합니다. 시간 처리는 브라우저의 현지 시간 기준입니다. 개선 후 예상 점수를 임의로 제시하지 않고 재측정을 유도합니다.

## 저장 구조와 Supabase 연결 (선택)

기본은 `localStorage`의 `classroom-air-records-v1`에 저장합니다. 같은 브라우저·접속 주소에서 새로고침 후에도 유지되지만, 브라우저 데이터 삭제·시크릿 모드 종료 시 사라질 수 있습니다. 로컬 기록은 기기 간 공유되지 않습니다. 저장 권한/용량 오류는 화면에서 실패로 표시하고 분석 결과는 유지합니다.

1. Supabase 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행합니다.
2. `config.js`에 프로젝트 URL과 **publishable 키 또는 legacy anon 키**를 넣습니다. `service_role`/secret 키를 넣으면 안 됩니다.
3. 페이지를 새로고침합니다. 분석 저장 시 로컬에 먼저 저장하고 REST API로도 저장합니다.

```js
export const config = {
  url: 'https://YOUR_PROJECT.supabase.co',
  key: 'YOUR_PUBLISHABLE_KEY'
};
```

SQL은 공개 발표용 데이터의 읽기·추가만 허용하는 RLS 정책입니다. 개인 식별 정보나 민감한 체감 메모는 저장하지 마세요. 비공개 운영은 Supabase Auth와 사용자별 RLS 도입이 필요합니다. 구성 방법은 [Supabase API 키](https://supabase.com/docs/guides/getting-started/api-keys), [RLS 문서](https://supabase.com/docs/guides/database/postgres/row-level-security), [REST API](https://supabase.com/docs/guides/api)를 참고했습니다.

클라우드 오류/8초 시간 초과 시 로컬 저장을 유지하고 메시지를 표시합니다. 미전송 기록의 자동 재전송 기능은 없습니다. 조회는 원격 최신 1,000개와 로컬 기록을 UUID로 합칩니다. 원격 기록을 로컬에 자동 캐싱하지 않으므로 오프라인에는 이 브라우저에서 직접 저장한 기록만 보입니다. 점수는 조회할 때 현재 알고리즘으로 재계산하며, 저장 시점의 분석·제안도 payload.analysis에 함께 보관합니다.

## 2026-10-28: 항목별 간편 입력 / 측정값 입력

- 온도·습도·CO₂·조도·소음 각각에서 입력 방식을 선택합니다. 기본값은 간편 입력이며 체감 응답을 직접 선택해야 합니다. 모르면 '잘 모르겠어요'를 선택합니다.
- 측정값 입력을 선택한 항목만 숫자가 필수입니다. 입력 방식을 바꾸면 사용하지 않는 입력은 저장·검증에서 제외됩니다.
- 간편 응답은 숫자로 추정하지 않습니다. CO₂는 답답함만으로 농도를 판정하지 않습니다.
- 측정 0개: 점수 없음 / 1~4개: 측정 항목 평균 / 5개: 종합 쾌적도. 미측정은 적정 판정이나 0점으로 처리하지 않습니다.
- 그래프와 시간대별 평균은 해당 항목의 실제 측정값만 사용합니다. 종합 점수 통계는 5개 모두 측정한 기록만 사용해 서로 다른 측정 범위의 점수가 섞이지 않게 합니다.
- 전후 비교는 양쪽에 수치가 있는 항목만 변화량을 계산합니다. 점수 변화는 두 기록의 측정 항목 구성이 같고 1개 이상일 때만 계산합니다.
- 기존 기록은 모두 '측정값 입력'으로 해석합니다. 새 기록의 inputModes/responses와 미측정 null은 기존 Supabase payload JSON에 저장되므로 테이블 변경은 필요 없습니다.
- 배포: classroom-air-update.zip 안의 index.html, styles.css, app.js, analysis.js, insights.js 5개를 GitHub 동일 위치에 덮어쓰세요. 설정이 들어 있는 config.js는 변경하지 마세요. Vercel 자동 재배포 후 확인합니다. 이 ZIP에는 연결 설정이 포함되지 않습니다.


## 2026-11-18: 질문형 체감 입력과 클라우드 오류 수정

- 항목별 간편 입력에서 8가지 구체적인 질문에 5단계(전혀 아니다 / 아니다 / 보통이다 / 그렇다 / 매우 그렇다) 또는 잘 모르겠어요로 응답합니다. 미리 선택하지 않습니다.
- 그렇다/매우 그렇다 응답은 체감 개선 안내에 반영합니다. 측정값이나 환경 점수로 환산하지 않습니다. 실제 측정값과 함께 입력할 수 있습니다.
- survey에 개별 응답을, responses에 요약을 저장합니다. 기존 JSON payload를 그대로 사용하므로 이번 기능을 위한 Supabase 테이블 변경은 없습니다. 이전 간편 기록도 조회되며 수정할 때에는 새 질문에 답해야 합니다.
- 브라우저 fetch 호출의 수신 객체 오류(Illegal invocation)를 수정했습니다. 실제 브라우저에서 모의 클라우드 조회 실패→성공 전환을 검증했습니다.
- 실패 원인을 권한/키/테이블/네트워크/시간 초과로 안내합니다. 새로고침 중 중복 클릭을 막고 성공하면 이전 실패 메시지를 갱신합니다.
- 배포된 Project URL은 점검 당시 DNS NXDOMAIN을 반환했습니다. 정상 실행 중인 프로젝트의 Connect 또는 Data API에 표시된 Project URL과 공개 키가 config.js와 일치하는지 별도로 확인해야 합니다. URL이 바뀌면 같은 프로젝트의 공개 키도 확인하세요.
- 공식 참고: https://supabase.com/kb/troubleshooting/nxdomain-error-connecting-to-a-supabase-project

## 2026-11-18: 학교·교실 선택과 비교, 구체적인 실천 안내

1. 환경 측정에서 학교와 교실을 드롭다운으로 선택합니다. 학교가 없으면 ‘학교 등록’을 열어 시·군·구와 정식 학교명을 입력합니다. 공백과 전각 문자는 정규화하여 학교 ID를 만들며, 약칭 대신 정식 이름을 사용해야 동일 학교로 분류됩니다.
2. 기본 교실 목록은 1~3학년 각 1~20반과 과학실·음악실·미술실·컴퓨터실·도서실입니다. 실제 학교의 구성에 맞추려면 classrooms.js의 defaultRooms를 편집하세요. 기존 id는 변경하지 마세요. 다른 학년/특별실도 고유 id로 추가할 수 있습니다.
3. 학교 목록은 이 브라우저에 보관하며, 앱을 열거나 환경 기록을 새로고침할 때 조회된 클라우드 기록의 학교도 목록에 추가합니다. 등록만 하고 기록을 저장하지 않은 학교는 다른 브라우저에 공유되지 않습니다. 동일한 Supabase 프로젝트에 연결된 앱끼리 공유합니다.
4. 기록은 schoolId + roomId로 구분하므로 같은 반 이름의 다른 학교가 섞이지 않습니다. 이전 학교 정보가 없는 기록은 그대로 보존하고 학교 간 비교에서 제외합니다. 기존 기록을 수정하여 학교·교실을 지정할 수 있지만 현재 수정 기능은 브라우저에만 적용됩니다.
5. 환경 기록의 ‘다른 학교·교실과 비교’에서 우리 교실과 범위를 선택합니다. 조회 기간 내 5항목을 모두 측정한 실제 기록만 교실별 평균을 냅니다. 우리 교실 평균, 다른 교실 평균, 점수 차이, 측정 횟수, 공동 순위를 표시합니다. 같은 학교만 비교할 수도 있습니다.
6. 다른 교실 평균은 각 교실 평균의 단순 평균입니다. 예시·간편/부분 측정·학교 미등록은 제외합니다. 현재 조회된 최대 클라우드 1,000개와 로컬 기록 범위이며 전국 통계가 아닙니다. 측정 시간·기기·수업 차이를 통제하지 않으므로 상대적인 참고 자료로 사용합니다. 비교 데이터가 없는 경우 수치를 만들지 않습니다.
7. 개선 안내는 원인 확인 → 구체적인 조절 행동 → 같은 위치에서 재측정하는 3단계로 구체화했습니다. 설정 변경은 선생님과 상의합니다. 기존 점수 기준은 변경하지 않았습니다.
8. 클라우드 조회 실패 후 남아 있는 경고가 로컬 저장까지 막던 문제도 수정했습니다.

classroom-air-comparison-update.zip을 풀어 안의 9개 파일을 GitHub 기존 파일과 같은 위치에 업로드하세요. classrooms.js와 survey.js도 반드시 함께 올립니다. config.js는 포함하지 않아 현재 연결 설정을 보존합니다. Vercel 배포 후 새로고침하세요. 새로운 학교 정보도 기존 payload JSON에 저장하므로 Supabase 테이블 변경은 필요 없습니다. 외부 학교 데이터를 자동 수집하지 않습니다.
